Proactive Event-Driven Agent

App SotaAgents độc lập — agent chủ động phản hồi theo Event, tái dùng POST /workspace-chat của Core.

Nguyên tắc cốt lõi: chỉ code trong App, KHÔNG sửa Core. Gọi chat bằng session của chính member → conversation + credit đúng người.

App thuần · Không sửa Core

1. Tổng quan kiến trúc

App gồm 2 phần chạy trong repo sotaagents-app-proactive-agent. Core chỉ là API được gọi.

App_Backend

Nhận & định tuyến Event

Nhận Event qua webhook (xác minh chữ ký HMAC), đọc Subject (member). Online → đệm cho Surface poll; Offline → lưu Event_Queue. Đánh dấu đã xử lý để không lặp.

App_Surface

Giao diện + gọi chat

Native module trong workspace chat (slot workspace.nav), chạy trong trình duyệt member (có session). Nạp Context và gọi /workspace-chat bằng session member, render câu trả lời.

Core

Workspace_Chat_API

API chat sẵn có. App không tự chạy LLM loop. Core gắn conversation + trừ credit theo member đăng nhập của lượt gọi.

3. Vòng đời một Event (chi tiết)

  1. Nhận Event. Nguồn ngoài gửi POST /events/proactive kèm chữ ký HMAC-SHA256 trên raw body. Backend xác minh chữ ký (sai → 401), đọc memberId (Subject). Thiếu Subject → 422.
  2. Định tuyến theo presence. Member online → đệm cho Surface poll. Member offline → lưu vào Event_Queue theo member (không chạy agent, không tốn credit).
  3. Nạp Context. App diễn giải payload nghiệp vụ thành turn text, kèm chỉ dẫn hành động (“tóm tắt + đề xuất, tra KB nếu cần”). Payload đầy đủ được đưa vào để agent có giá trị thật, không chỉ tên field.
  4. Kiểm soát nhịp. Gộp event dồn dập → tối đa một lượt/cửa sổ; trần lượt/member; chỉ loại event “đáng phản hồi” mới chạy, loại khác chỉ ghi nhận.
  5. Chạy lượt agent. Surface gọi POST /workspace-chat bằng session member → Core gắn đúng conversation + trừ đúng credit; SSE trả lời stream về.
  6. Render & đánh dấu. Câu trả lời hiển thị trong giao diện App; Event được ack/đánh dấu đã xử lý để không lặp.

4. Mô hình dữ liệu

MemberConversationMap

member → conversationId tất định (deriveConversationId). Mỗi member đúng một hội thoại.

Event_Queue

Theo member; mỗi event {type, payload, subject, receivedAt, status: pending|processed}.

PresenceState

member → online/offline, theo heartbeat poll của Surface (TTL).

RateState

Đếm lượt/member trong cửa sổ + trạng thái debounce (gộp).

5. Các tính chất đúng đắn (Correctness Properties)

P1Không sửa Core — toàn bộ code trong repo App, chạy với Core không đổi.
P2Credit đúng member — mọi lượt gọi bằng session member, không dùng service account.
P3Offline không tiêu credit — chỉ ghi Event_Queue, không chạy agent.
P4Event không mất — event offline nằm trong queue tới khi xử lý hoặc hết hạn.
P5Không xử lý lại — event đã xử lý được đánh dấu, không tạo lượt mới.
P6Một hội thoại/member — ánh xạ tất định.
P7Kiểm soát nhịp — event dồn dập tạo tối đa một lượt/cửa sổ; loại không đáng phản hồi không tạo lượt.

6. Endpoint chính

EndpointVai trò
POST /events/proactiveNhận Event từ nguồn ngoài (HMAC verify). 202 accept · 401 sai chữ ký · 422 thiếu Subject.
GET /events/pollSurface poll khi online (kèm heartbeat giữ presence). Trả event đã đệm + Context.
POST /events/ackAck event online đã xử lý.
GET /events/pendingSurface lấy event tồn khi mở lại (offline queue).
POST /events/pending/ackĐánh dấu event tồn đã xử lý (không lặp).
GET /api/helloTrả identity member (org/workspace/user) từ token đã verify — Surface dùng để suy conversationId.

7. Ghi chú vận hành

Nhận diện member: Surface lấy userId từ /api/hello (claim đã verify) thay vì auth store của host — vì native module không luôn được hydrate store.

Gọi backend qua tunnel: các route /events/* gọi qua useAppFetch (đường app-scoped). Endpoint Core như history gọi /api/history/:id/messages bằng fetch same-origin.

Lịch sử hội thoại: host useChatSession không tự nạp history; App tự fetch history của conversation rồi hợp nhất (dedupe theo id) với lượt phiên để hiển thị.

Ẩn bong bóng event: lượt do event tự sinh được ẩn khỏi transcript (chỉ hiện câu trả lời của agent); tin member gõ tay vẫn hiện bình thường.
